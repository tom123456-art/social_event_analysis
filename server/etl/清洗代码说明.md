# 清洗代码说明

`cleaning` 按功能组织，只有以下四个类，不再保留清洗调度类或表达式包装类。

| 类 | 修改入口 |
| --- | --- |
| `TextNormalizer` | HTML、控制字符、链接、重复标点和空白处理，所有文本字段共用规则 |
| `FieldNormalizer` | 字段映射、缺省值、平台和类别归一化、数值和时间解析、长度限制、结构对齐 |
| `RecordFilter` | 原始损坏检查、异常标记、无效和空记录过滤、拒绝原因 |
| `RecordDeduplicator` | 内容键、批内保留优先级、增量保留优先级、重复数 |

## 调用顺序

`HotspotAnalysisJob` 直接调用各项功能：

1. `FieldNormalizer.prepareEvent` 补齐事件信息。
2. `RecordFilter.inspectRaw` 标记原始损坏，原字段继续保留用于隔离输出。
3. `TextNormalizer.normalize` 共用文本处理，生成 `_normalized_*` 临时列与分析正文。
4. `FieldNormalizer.normalize` 投影标准字段并应用长度限制，移除临时列。缺失内容 ID 的哈希仍基于原字段。
5. 调用现有 `InteractionHeatCalculator`，互动指标不放在规范化类中。
6. `RecordFilter.retainUsable` 过滤不可用记录并移除内部质量标记。
7. `RecordDeduplicator.deduplicate` 批内去重；增量合并使用 `deduplicateIncremental`。两者均返回保留记录和重复数，作业不再处理去重序号。

乱码必须在文本规范化之前检测。过滤条件、人工审核优先级和最近采集版本覆盖规则保持不变。
`text_normalized` 比较规范化前后的完整文本，覆盖 HTML、链接、标点和空白修复，不将长度截断算作格式修复。
乱码规则继续读取共享的 `resources/rules/text-quality-rules.json`，不维护另一份乱码正则。

## 验证

编译与打包：`mvn -f server/pom.xml -pl etl clean package -DskipTests`。
本项目回归入口为 Java `main`，不由 Surefire 自动执行；打包通过不代表回归已经执行。

在与项目相同版本的 Spark 上，构建测试包后运行：

```sh
jar --create --file server/etl/target/etl-regressions.jar -C server/etl/target/test-classes .
spark-submit --master 'local[2]' \
  --jars server/etl/target/etl-1.0.0-SNAPSHOT.jar \
  --class com.social.hotspot.etl.CleaningRegression \
  server/etl/target/etl-regressions.jar
```

`CleaningRegression` 覆盖文本规则统一、修复标记、原始损坏证据、无效记录过滤、内容哈希和两种去重。
既有 HTML/互动、文本损坏、时间、来源排名、情感和仓库回归也应一并执行。
类名变化不需要 SQL 迁移，正式任务入口及部署 JAR 路径保持不变；虚拟机需要更新构建后的 ETL JAR。
